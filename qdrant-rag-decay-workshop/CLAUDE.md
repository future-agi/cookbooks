# Qdrant × Future AGI — Agentic RAG Workshop

## Project status (last updated 2026-08-03)

**The workshop is built, measured, and verified end-to-end** against the live Qdrant Cloud cluster (v1.18.3). Read this file top to bottom for the current state and the decisions that bind; `README.md` explains how to run it, `RUNBOOK.md` carries the run of show, expected numbers, fallbacks, and rehearsal gates.

**What this is:** a live, one-hour joint technical webinar run by Dylan (Qdrant) and Rishav (Future AGI). The story: an agentic RAG system worked well on a small corpus and quietly decayed as it grew. Three flaws were latent from day one; growth exposed them. We show the quality sliding, find why each metric slid on the Future AGI dashboard, fix the right layer in Qdrant, and prove each fix worked by re-running the same 37 golden queries. The audience is AI/ML engineers running agentic RAG in production; they leave with a repeatable workflow: measure → locate the failing layer → fix that layer → re-run the same queries → verify the number moved.

**Three surfaces, three roles:** the Streamlit app is where the audience experiences failures (chat + retrieval panel showing sprite, doc_id, generation badge, rank, score; the panel shows PANEL_K=10 while the agent reads TOP_K=5, so the audience can see the right document sitting below the cutoff). The notebook is where fixes are applied, one section each. Future AGI is where traces and judged scores prove it worked — each re-measure cell quotes its dashboard read in one line of prose, and the notebook renders exactly ONE score table (the §7 recap, which doubles as the offline fallback if the platform can't score live). Hard boundary: the app never displays eval scores.

## What exists and runs (all verified live)

- `helpers/` — PokéAPI corpus, chunking, embeddings (+`warmup()`), UI, dedup, config. Corpus: the full Pokédex, 1,025 species / 6,029 docs (5.3MB slimmed cache). Duplication is skewed per doc, seeded on doc_id (35% single copy, long tail to 8×, avg ~2.7×) — realistic re-crawl accumulation; the stale conflict docs pin the top of the tail; gold docs stay single-copy in every ingest. Chunks are 110 chars.
- `ingest.py` — broken-on-purpose baseline (weak dense only, duplicates, small chunks, no index) into `pokemon_webinar` (22,946 pts), plus `pokemon_viz` (240 pts; 7 recognizable Pokémon; Snorlax and Gengar carry the 6× clusters) for the Web UI point-cloud beat. Resets the retrieval state file.
- `prep.py` — offline: adds strong/sparse/ColBERT named vectors to the live collection (`create_vector_name`, zero downtime) and backfills them with `update_vectors` (payloads untouched — `upsert` would wipe them). Backfill is resumable; the encoder can get OOM-killed on long runs, rerun until clean. Snapshots both collections when done.
- `agent.py` — LangGraph ReAct agent, one tool (Qdrant search), strict grounding prompt, file-backed retrieval switch (`minilm`/`bge`/`hybrid` + `current_only`) the notebook flips and the app reads per question. Registers Future AGI tracing at import, so notebook, app, and scripts all export traces. `RECURSION_LIMIT = 12` caps re-search loops and returns an honest "I don't know" instead of crashing. Exact search everywhere for reproducible numbers.
- `app.py` + `helpers/ui.py` — Pokédex-themed Streamlit chat (light, high contrast, readable from across a room) + retrieval panel + mode badge; warms all models at boot. The panel's duplicate badge keys on `(doc_id, text)`, the same key as the notebook's dup_rate and `verify_arc.py`, so the two surfaces always agree.
- `workshop.ipynb` — the fixes, one section each; every narration claim is measured from the committed run/score files (see "Verified arc").
- `run_golden.py` — golden set through the traced agent, once per stage; `--stage iterN` selects that stage's Future AGI project (`STAGE_PROJECTS`: `pokedex-webinar`, `…-fix1-dedup`, `…-fix2-bge`, `…-fix3-hybrid`, `…-fix4-filter`) and refuses `--group` alongside `--stage`. Ad-hoc app/notebook traffic lands in `pokedex-rag`. Writes `data/golden_run-{stage}.jsonl` with answers and `retrieved_context`.
- `score_runs.py` — off-camera: scores the runs on the five trace evals + the custom answer-correctness judge, appends per row, resumes after outages, and detects a regenerated run file instead of silently mis-averaging.
- `snapshot.py backup|restore|download`, `verify_arc.py` (`--baseline-only` = non-destructive flaws-show-red gate), `scaling_curve.py` (self-contained `pokemon_scale` collection; already exact-search).
- `data/golden_dataset.jsonl` — 37 queries: cold_open 1, fix1 3, fix2 14, fix3 18, multi_hop 1. Gold labels are doc-level (never point-level: fixes re-ingest and re-embed, point ids don't survive; every chunk carries a stable `doc_id`). The fix3 queries are LLM-mined paraphrases of gen-1 flavor text; the fix2 set includes clone-crowding queries where MiniLM retrieves a later-gen lookalike. Run/score files under `data/` are committed so every quoted number is reproducible.

**Cluster:** only `pokemon_webinar` and `pokemon_viz` exist. Both have cluster-side snapshots (restore in seconds) plus local `.snapshot` files (461MB webinar) as the fresh-cluster path. Current state: restored broken baseline (22,946 / 240), state file `{"mode": "minilm", "current_only": false}`, `verify_arc.py --baseline-only` passing all-red.

## Locked decisions

- **Framework:** LangChain locked; in practice LangGraph's `create_react_agent`, because `traceAI-langchain` requires `langchain<0.4` (stack pinned to langchain 0.3.x / langgraph 0.6.x; move to `langchain.agents.create_agent` when Future AGI supports 1.x). traceAI auto-instruments LangGraph, so Qdrant searches appear as retriever spans with no manual span code.
- **Generator:** `anthropic:claude-haiku-4-5`, locked (via `init_chat_model` provider string; a Vertex Gemini experiment was reverted — judged answer numbers belong to the generator that produced them, and Gemini erased the narrated behaviors). Small is deliberate: fast, and less prone to answering from memorized Pokémon knowledge.
- **Corpus:** Pokémon via PokéAPI. Fun, instantly obvious right/wrong answers, and a real outdated-doc conflict (typings and the type chart genuinely changed across generations). Nintendo IP is fine for the live demo; never publish the corpus as a downloadable artifact.
- **Three scored fixes, in order:** dedup → embedding migration → hybrid + rerank, then the `is_current` payload filter closes the cold open. Multi-hop is a trace-only bonus beat, not a scored fix.
- **Cold open:** the Steel Ghost/Dark resistance question, not Magnemite typing — Magnemite leaks from the generator's parametric memory; the obscure Steel fact does not. It works because the generator cites by name only, type-chart docs are never chunked, and the stale Gen-5 chart is over-duplicated so it wins baseline retrieval.
- **Generation lives in the payload, never in document text, and the model never sees the generation tag** (`_format_for_model` shows name + text only; the app panel shows the badge). If the model saw the tag, it could resolve staleness itself and the cold open dies. Three files cooperate on this constraint (`helpers/corpus.py`, `agent.py`, `helpers/ui.py`) — don't relax any of it.
- **Strong model is `BAAI/bge-large-en-v1.5`** (mxbai collapsed under duplicate crowding). bge queries need the manual instruction prefix — FastEmbed omits it (`helpers/embeddings.py`).
- **Hybrid's dense arm is bge**, so the fixes compose: dedup → migrate → hybrid on top. Sparse arm is miniCOIL (`Qdrant/minicoil-v1`, named on camera as Qdrant's learned sparse model); rerank is ColBERT as a MAX_SIM multivector.
- **Fix #1 is scored on duplicate-rate (and now answer correctness), not Precision@K** — duplicating gold docs would raise Precision@K, so the planted duplicates are distractors and gold stays single-copy.
- **The flaws are planted and the notebook says so** (section 1 disclosure): skewed re-crawl copies, one over-copied stale chart, 110-char chunks. The measurements on top are real — that sentence is what keeps a skeptic who reads `ingest.py` on side.
- **Broken-on-purpose staging:** `ingest.py` ships the broken state; each fix is applied live as notebook cells against the running collection, never by re-running a "fixed" ingest.
- **Code is part of the show:** anything on camera (notebook cells, `agent.py`) contains Qdrant and Future AGI calls verbatim and nothing else; plumbing lives in `helpers/`, which the camera never opens.

## Verified arc (Haiku runs + scores, new FI account, 2026-08-03)

Decay curve: recall@5 0.67 → 0.45 → 0.39 and dup-rate 0.44 → 0.51 → 0.52 at Gen 1 (1,314 pts) / Gen 1–4 (8,351) / full dex (22,946) — real growth stages: a doc exists once its species is in the dex AND its facts have shipped.

Scoreboard spine (per stage: baseline → dedup → bge → hybrid → filter):

- **Answer correctness (custom judge): 0.68 → 0.81 → 0.95 → 0.92 → 0.95**; failures 12 → 7 → 2 → 2 → 2. Cold open stays 0.0 through every retrieval fix and goes 1.0 only with the filter.
- **Searches per question: 2.00 → 1.59 → 1.19 → 1.14 → 1.16** (questions needing 2+ searches: 16 → 9 → 4 → 3 → 3). Haiku never refuses (0/37 at every stage); it papers over bad retrieval by re-searching with new wordings, so the answer often comes out right and only traces show the cost. This replaced the old refusal narrative and is the latency/cost story.
- Trace metrics iter1–iter3 (canonical in `data/scores-iter*.jsonl`): relevance 0.85 → 0.90 → 0.94, utilization 0.65 → 0.61 → 0.61, groundedness 0.95 → 0.92 → 1.00, attribution 0.95 → 0.92 → 0.97, no-hallucination 0.95 → 0.95 → 0.92. **iter4/iter5 trace columns are ⟨pending⟩ in the notebook** — see Operational state.

Per fix: dedup 22,946 → 8,416 pts (viz 240 → 95), duplicate rate 0.67 → 0.00, queries with a duplicate in top-5 36/37 → 2/37; specimen is Snorlax ("Snorlax is a Normal-type Pokemon." ×5 → starved answer). Fix #2 A/B recall 0.64 → 1.00 (n=14); the cheek-pouch answer flips Pichu → Pikachu, and the bge flip also fixed four paraphrase failures outside its slice. Fix #3 A/B (n=18): recall 0.78 → 0.89, NDCG@5 0.61 → 0.77, MRR 0.55 → 0.73; hybrid recall wobbles 0.89/0.94 on RRF ties (one gold doc flips rank 5↔7 — runbook note, both a win); attribution: the pool at rank 20 holds gold for 0.94 of queries, fusion-only top-5 scores 0.72 (below pure dense 0.78), the ColBERT rerank converts it; marowak absent from dense top-30 → hybrid rank 1; one honest regression (tumbling-barriers 11 → out of top 30). Fix #3's framing: by iter3 the answer column is nearly green, so the beat is "the agent compensates for mis-ranking; rank-sensitive gold-label metrics see what answer metrics can't."

**Steel arc (the workshop's spine): wrong → hedge → wrong → hedge → right.** Baseline: "Yes!" wrong (8 stale copies fill the panel, gen6 at rank 9). Dedup: hedge ("depends on the generation" — both charts reach the top-5). bge: wrong again (stale chart back on top). Hybrid: hedge (both charts at ranks 1–2). Filter: correct, grounded in `typechart-steel-gen6` alone. Ranking at its best only surfaces the conflict; currency lives in metadata. The judge fails hedges by design ("the question asks for one fact"), which is what keeps the filter as the fix that closes the arc.

Measured surprises the narration leans on (don't smooth these away): utilization went DOWN after dedup (copies of the used chunk all counted as utilized) and stayed flat through every retrieval fix — a generator metric in a retrieval costume; no-hallucination dipped at iter3 with groundedness 1.00 on the flagged rows (the two judges disagree on purpose — better retrieval exposes generator embellishment); every trace eval stayed green on the stale-doc answers. The two failures that survive everything: the Charizard entry (the accepted fragmentation tension made visible) and an Omanyte-vs-Kabuto fossil sibling confusion.

**Known accepted tension:** fragmentation (110-char chunks) is planted but never fixed — dedup removes copies, not truncation. Load-bearing beats answer correctly anyway because chunks carry `[name]` tags and type-chart docs are never chunked. If a beat ever needs whole flavor text, the fix is a re-chunk + re-backfill, which is NOT stageable live.

**Biggest standing risk: every LLM knows Pokémon.** Mitigations, all in place and re-verified with Haiku: the hard grounding prompt (also forbids guessing a name and searching to confirm it), golden questions biased to facts models don't memorize, and rehearsal must confirm wrong retrieval produces wrong answers. If a future generator change leaks parametric knowledge, pick a weaker model — a weaker generator makes this demo better.

## Future AGI: eval design and measured behavior

**Tracing (verified live):** `register(project_type=ProjectType.OBSERVE, project_name=…, metadata={"stage": …})` + `LangChainInstrumentor().instrument(tracer_provider=…)` at agent import. One project per fix stage; a root "Pokedex Agent" span per question carries `input`, `output`, `retrieved_context` (every hop concatenated — score against only hop 1 and the hallucination judge raises phantom flags), and `expected_answer` (golden runs only). Map platform evals to that root span.

**The answer-correctness judge is a CustomLLMJudge, because no built-in judges against ground truth the way the cold open needs** (verified against the live registry): `factual_accuracy` takes input/output/context and scored the confidently-wrong Steel answer 1.0 — it cannot see a stale-but-relevant doc; `ground_truth_match` matches the reference's wording and failed a correct answer both for being terser and for adding grounded detail. The judge runs via `evaluate(prompt=…, engine="llm", model=…)` with a stronger model than the generator (`JUDGE_LLM`, default `anthropic/claude-sonnet-5`); its criterion must fail hedges or the hybrid stage passes and the filter stops closing the arc. The full criterion is on screen in notebook section 5 — showing the rule is what makes the judge trustworthy.

**Registry identifiers confirmed:** `context_relevance`, `chunk_utilization`, `chunk_attribution`, `groundedness`, `factual_accuracy`, `detect_hallucination`. Working recipe: `evaluate([...], input=…, output=…, context=<ONE STRING — a list 500s>, model="turing_flash")`. Platform display names are Title Case; verify exact identifiers with Rishav before they go on a slide. Agentic/conversation evals (Tool Call Accuracy, Trajectory Match, …) exist by name but their schemas are unconfirmed — never script a scored beat on them.

**Measured triad behavior:** `groundedness` stays green through retrieval failures (an answer grounded in the wrong document passes) — retrieval-vs-generation separation works; `context_relevance` dips on misses, never collapses (Pokémon text is all topically similar); `chunk_utilization` scores the answer's use of context, NOT duplication. The reproducible take-home skill is the triad read: low relevance + low utilization → fix retrieval (Qdrant); high relevance + low utilization or failing groundedness → generation side.

**`POST /sdk/api/v1/new-eval/` (standalone evals) is unreliable — the arc does not depend on it.** Documented windows: five outages on 2026-08-03 morning across two accounts (HTTP 500 `server_error`, no Retry-After, no rate-limit headers; request IDs for their team: `d933f406-f654-4c70-b358-f5d2d2702ab4`, `7fcf6610-3f00-4247-9285-844ae04f599a`, `3522f098-4836-40e8-a8f5-ee6499e2e9fb`), plus a fourth independent window the same evening lasting 1.5+ hours — during which trace ingestion and the `engine="llm"` judge path stayed up. Retry cadence is not the cause (failures hit the first call of fresh sessions; when up, the endpoint takes a call every ~10s for 37 rows). SDK gotchas: on failure `evaluate()` still returns `status="completed"` with `score=None` and the error in `reason` — a missing score is the only reliable failure signal; calls must stay sequential (at four in flight it dropped a quarter).

**Open question that decides show-day risk: do dashboard evals share the `new-eval` backend?** Ask Rishav to run the triad on a traced project while the endpoint is 500ing. If dashboard evals work, the flaky endpoint never touches the webinar (it only pre-computes the notebook scoreboard). If they share the backend, no "after" number can be measured live and every number gets pre-baked and read from committed files.
